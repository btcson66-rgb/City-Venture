# 好玩優先：短循環設計（#182）

研究日期：2026-10-11。先提交這份設計，再改遊戲。以下是本遊戲的設計假說，不能把 bot 的速度當成人類初玩速度，也不能把「多巴胺」當成已量測的生理結果。

## 參考與直接做法

| 研究來源 | 本遊戲可直接採用的做法 |
|---|---|
| [Juice It or Lose It，Jonasson / Purho](https://www.gdcvault.com/play/1016487/juice-it-or-lose) | 真實收款用現有收銀音與金額飄字；完成目標有短暫彩帶、進度前進，效果不能擋輸入。 |
| [The Art of Screenshake，Nijman](https://www.youtube.com/watch?v=AJdEqssNZ-U) | 動作與結果在同一時刻回應；經營遊戲採局部彈跳而非持續搖鏡。影片本次讀取失敗，僅列研究方向，不聲稱已觀看。 |
| [Designing Game Feel: A Survey，Pacheco 等](https://arxiv.org/abs/2011.09201) | 將反饋強度配合事件的重要性：小目標輕叮、首次成就卡、大章節原有章節卡。 |
| [Don't Juice It or Lose It，Kelly](https://www.gdcvault.com/play/1021398/Don-t-Juice-It-or) | 彩帶只用於真實成果，短且可穿透；不把每次扣款也變成慶典。 |
| [The Gamer's Brain，Hodent](https://media.gdcvault.com/gdc2017/Presentations/Hodent_Celia_TheGamersBrain.pdf) | 明確、可理解的目標比外在獎勵堆疊重要。保留一個下一步；固定里程碑負責引導，隨機驚喜只增添變化。 |
| [Game Dev Tycoon，開發者介紹](https://www.greenheartgames.com/) | 從小工作開始，完成作品、得到成果、解鎖下一個選擇；取消強制等月底，升遷是新頭銜與下一階工作。 |
| [Stardew Valley，開發者介紹](https://www.stardewvalley.net/about/) | 行動累積成長、解鎖探索與新選擇；等待期間允許工作、探索或主動跳到下一件事。 |
| [GitHub awesome-game-design](https://github.com/Roobyx/awesome-game-design) | 用設計文件、postmortem 和學習資源作研究索引；索引不是遊戲成效的實證。 |
| [Two Point Hospital 官方入門指南](https://support.sega.com/hc/en-gb/articles/360000328457-Getting-Started) | 把短期目標與進度摘要放在持續可見的位置；新區域用成果解鎖，不讓玩家猜下一件事。 |
| [Goal-gradient 研究，Kivetz / Urminsky / Zheng](https://www.columbia.edu/~rk566/Session4/Goal-Gradient_Illusionary_Goal_Progress.pdf) | 接近目標可促進行動；原研究是消費獎勵情境，套用遊戲是推論。只顯示真實進度，不贈送假完成格。 |

Core loop：選一個小目標 → 親手做 → 看見真實成果 → 決定下一步。Session loop：第一次銷售 → 正式創業 → 第二項商品 → 招人 → 第一份大合約。Compulsion loop 在本作代表想試下一個選擇；不以錯過懲罰、付費隨機獎勵或無限簽到要求留住玩家。

固定獎勵排程：完成目標、首次收款、升遷都可預期。變動回饋：工作台詞與客人的小驚喜；不能成為主線必要條件。Goal gradient 是本輪的設計假說：显示「1/2 商品」與章節進度，讓剩下的一步看得見，仍須初玩實測。

## 五個前期卡點

| 卡點 | 修改目標 | 經濟與舊檔界線 |
|---|---|---|
| 第三章等月底 | 保留 goal_month id，改為主動上架兩項商品 | 舊的完成收據仍有效；不偽造月結。 |
| 等庫存 | 既有首次快速送貨 + 跳到排程事件 | 真實採購、送貨與成本照跑。 |
| 等首單／交付 | 等待目標提供下一事件按鈕 | 正常需求與貨運處理，不額外贈送收入。 |
| 等 Daniel 的週四會面 | 下一事件包括 NPC 下一開門時間 | 原有會面與選擇仍須玩家操作。 |
| 打工一次就停／看不見成長 | 可選接續工作、可見升遷進度、首次成就 | 時薪隨真實班次與評價；不加無來源連擊金錢。 |

## 前三十分鐘計畫與量測

| 真實分鐘（設計目標，尚非實測） | 玩家行動 | 進展回饋 |
|---|---|---|
| 0–2 | 到城、看通知、出門 | 第一個目標完成 |
| 2–4 | 喝咖啡、找到共享空間 | 城市與下一步清楚 |
| 4–6 | 選生意、買貨 | 庫存與進度增加 |
| 6–8 | 拍照、上架 | 第一個商品 |
| 8–10 | 真實首單、寄件 | 訂單／交付慶祝 |
| 10–12 | 處理首次客訴 | 恢復成功；可重試 |
| 12–14 | 註冊公司 | 首次成就與章節卡 |
| 14–16 | 開帳戶、選工作空間 | 下一項商品目標 |
| 16–18 | 上架第二項商品 | 第四章解鎖 |
| 18–20 | 聘員工或選打工 | 角色與工作變化 |
| 20–22 | 完成一班 | 工資、評價、升遷进度 |
| 22–24 | 選接續班或探索 | 自主選擇、新工作台詞 |
| 24–26 | 拜訪 Daniel | 新合約選擇 |
| 26–28 | 比較條件、接受／拒絕 | 故事回饋 |
| 28–30 | 採購／交付或下一事業 | 下一個短目標 |

最終 evidence 必須另附 bot 真實時間戳、各目標耗時、最長無進展間隔及超過五分鐘的失敗。人類新手的找路／閱讀時間仍需另測。計畫表不能取代驗收表。
