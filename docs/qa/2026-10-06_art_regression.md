## 這次驗證的範圍

- 新版基線上的完整單元測試，以及新增版面/目錄檢查。初次 932 項跑出 daily 漏翻 1 項，修正後單獨 7/7 透過，最終完整重跑 932/932 透過（348.8 秒）；結果見 `evidence/2026-10-06_visual_repair/raw/verified-unit-tests.log`。
- 80 張前端、街景、室內、地圖、黃昏/夜間與服裝商店巡覽，0 流程失敗，0 未翻譯畫面文字；另外單獨擷取全部城市區域，以及 Company OS 基礎頁籤的中英文與放大倍率。不能把不可進入建築的室內呼叫回退街景算作完成室內美術驗收。
- 40 條實際步行連線、出口方向與進入後防重觸發，0 流程失敗。其首次巡覽發現的 daily 已以上述執行期測試確認修正。
- `pose_check.py` 同時檢查走路與其他姿勢。此次曾抓到女性辦公服的裙擺/鞋之間斷層，修補同步小腿底層後透過，沒有忽略這個失敗。
- 本機 Quadro RTX 4000 / Godot 4.5.1 / 1280×720：獨立繪圖視窗暖機後，240 個實際牆鐘幀時間，中位數 16.646 ms、p95 16.971 ms、最大 17.588 ms；當下材質快取估算 391,042,524 bytes。這是短時桌面場景量測，不代表所有電腦或瀏覽器都能保持 60 FPS。
- 三天、每日 5,000 訂單、50 員工、兩公司與所有產業的短期壓測，`perf_check --short` 零失敗；包含材質快取巡覽。保留原 1.2 GB 快取預算；圖片解析度、圖層數與角色邏輯尺寸均未增大。
- Windows 正式匯出範本產生試玩 exe；實際執行原生繪圖 120 幀後 exit 0，執行記錄沒有 SCRIPT ERROR。正式包只作本機試玩，未上傳商城或合併主線。

## 防再犯的交付規則

1. 美術資源「存在、可載入」只能算資源檢查，不能代替遊戲畫面驗收。角色必須以實際圖層、方向、表情、動作與服裝組合驗證。
2. 同一變更同時檢查桌面、觸控、中文、英文、放大字型。視窗能捲動仍要保留可見的關閉/返回操作。
3. 地圖加寬、新增連線或換資源尺寸時，對照邏輯尺寸、物理圖片尺寸、背景覆蓋、碰撞、出口、導航與實際路線。不把填色面積當作完整景觀。
4. 每次修復新增能重現玩家問題的檢查；`test_visual_layout.gd` 自動由單元測試 runner 掃描，CI 加入角色合成的 pose_check。
5. 同時儲存修正前/後畫面、測試失敗與修正後結果、效能原始量測、基線 commit、試玩包 SHA256。不得把中途失敗刪掉後宣稱整輪全綠。
6. 最終檢查包含 export 後實際執行。來源預覽、匯出成功、玩家操作驗收分開記錄。品質主觀部分標為 READY_FOR_REVIEW，不因自動測試透過而宣稱所有美術問題永久消失。

## 另外觀察到的事項

- 上游完整測試的兩個大資料存檔案例會印出 `Decompression failed` 診斷，但測試的 round-trip 驗證本身透過。本次沒有修改 SaveCodec；此診斷應由存檔/穩定性工作追查，不能當作美術問題，也不能隱藏為「零 ERROR」。
- 數個尚未租用、沒有入口或沒有獨特室內配置的建築仍會使用既有回退。已保留原遊戲設計；本次沒有以裝飾改動冒充新增可玩內容。
- 尚未驗證低階硬體、長時 Web 記憶體與手機 GPU。短期壓測不等於十年存檔驗收。
